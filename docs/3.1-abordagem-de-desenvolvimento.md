# 3.1 Abordagem de Desenvolvimento

O projeto vai seguir uma abordagem iterativa e incremental, que é basicamente fazer o trabalho aos poucos, em etapas simples. A documentação e o código serão feitos juntos, começando pela visão geral e as regras do sistema (como a Descrição do Projeto), para só depois desenhar as telas, criar o banco de dados e programar a aplicação.

No final de cada etapa concluída, a gente revisa o que foi feito para ver se o texto e as ideias estão fazendo sentido, e salva a versão atualizada no repositório do GitHub. Os professores ou o cliente podem dar um retorno a cada entrega importante, o que ajuda a corrigir erros e mudar detalhes simples antes de ir para a próxima fase.

Escolhemos essa forma de trabalhar porque o modelo em Cascata tradicional é muito travado, já que ele exige planejar absolutamente tudo do começo ao fim sem poder mudar nada depois. Usamos do Scrum a ideia de dividir o projeto em entregas curtas, mas deixamos de fora as reuniões diárias (Dailies) e cargos formais como Scrum Master, já que a equipe é pequena e dá para conversar e decidir as coisas diretamente pelo WhatsApp ou na sala de aula.
