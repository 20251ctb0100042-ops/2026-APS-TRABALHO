# 4.2.1 Levantamento de Requisitos

## 1. Como os requisitos foram levantados

Os requisitos do sistema foram levantados em dois passos. Primeiro, através de uma **entrevista** com o Gabriel Schactae, meu irmão e proprietário da forneria de cookies, sobre as dificuldades de gerenciar o estoque de farinha, açúcares, chocolates e os tipos de caixas de envio. Depois, uma **conversa curta** com a equipe de apoio da cozinha para entender como é feita a baixa diária de embalagens.

O que está entre aspas na tabela a seguir foi dito por eles. A coluna da necessidade é interpretação minha, e foi validada com o Gabriel antes de virar requisito.

 **A confirmar com o cliente:** O Gabriel ainda vai definir se a baixa de embalagens será automática ao fechar o pedido ou feita manualmente no fim do turno. Adotei a baixa manual por item como padrão provisório.

## 2. Da fala à necessidade

| # | Fala | O que é | Necessidade por trás |
|---|---|---|---|
| F1 | "Preciso registrar cada farinha, chocolate e açúcar com a unidade certa de medida." (Gabriel Schactae) | necessidade | cadastrar e detalhar os ingredientes da forneria de cookies |
| F2 | "Falta caixa de entrega de 6 cookies direto porque ninguém avisa quando tá acabando." (Gabriel Schactae) | necessidade | cadastrar embalagens e emitir alertas de limite mínimo |
| F3 | "Quero dar entrada nas compras ou dar baixa no que foi usado na produção de forma simples." (Gabriel Schactae) | necessidade implícita | funcionalidade de atualização manual de saldos do estoque |
| F4 | "Quero ver em uma tela só o que está acabando para fazer a feira da semana." (Gabriel Schactae) | necessidade | tela central de consulta de estoque com alerta visual |
| F5 | "Só eu e a equipe autorizada podemos alterar o saldo dos ingredientes e embalagens." (Gabriel Schactae) | solução | controle de acesso com autenticação por login e senha |

## 3. Histórias de usuário

| # | História de usuário | Veio de |
|---|---|---|
| HU01 | Como **proprietário/confeiteiro**, quero **cadastrar ingredientes especificando nome, unidade de medida e limite mínimo**, para **padronizar a gestão da produção**. | F01 |
| HU02 | Como **proprietário**, quero **cadastrar embalagens com tipo, tamanho e limite de segurança**, para **garantir insumos de envio para o iFood**. | F02 |
| HU03 | Como **operador de estoque**, quero **atualizar a quantidade de saldo de ingredientes e embalagens**, para **manter o inventário alinhado com a realidade**. | F03 |
| HU04 | Como **proprietário**, quero **consultar o inventário com alertas de falta**, para **comprar materiais antes que afetem a operação**. | F04 |
| HU05 | Como **usuário do sistema**, quero **fazer login com senha**, para **proteger os dados de estoque da forneria de cookies**. | F05 |

## 4. Requisitos funcionais

| # | Nome | Requisito | Veio de |
|---|---|---|---|
| RF01 | Cadastrar ingrediente | O sistema deve permitir cadastrar ingredientes informando nome, unidade de medida (kg, g, L, un) e quantidade mínima em estoque. | HU01 |
| RF02 | Cadastrar embalagem | O sistema deve permitir cadastrar embalagens informando tipo, tamanho, quantidade atual e limite de segurança. | HU02 |
| RF03 | Atualizar saldo de estoque | O sistema deve permitir registrar entradas e saídas de quantidades de ingredientes e embalagens. | HU03 |
| RF04 | Consultar alerta de estoque | O sistema deve exibir a lista de suprimentos com destaque visual nos itens abaixo da quantidade mínima. | HU04 |
| RF05 | Autenticar operador | O sistema deve exigir login e senha para gerenciar ou alterar dados do estoque. | HU05 |
| RF06 | Filtrar inventário por categoria | O sistema deve permitir filtrar a visualização entre apenas ingredientes ou apenas embalagens. | HU04 |

## 5. Requisitos não funcionais

| # | Categoria | Requisito | Veio de |

| RNF02 | desempenho | A consulta ao inventário e atualização de saldos devem responder em menos de 3 segundos. | características da 4.1 |
| RNF03 | acesso | Apenas usuários autenticados como operadores podem alterar cadastros e saldos de estoque. | características da 4.1 |

## 6. Conferência com a 4.1

| Item do escopo (4.1) | Requisitos |
|---|---|
| O sistema cadastra novos ingredientes informando nome, unidade de medida (kg, g, L) e quantidade mínima em estoque. | RF01 |
| O sistema cadastra novas embalagens informando tipo (caixa, saco, laço), tamanho, quantidade disponível e limite mínimo de segurança. | RF02 |
| O sistema atualiza a quantidade de saldo em estoque a cada entrada de compra ou saída de produção/embalagem. | RF03 |
| O sistema exibe o inventário completo com destaque visual nos itens com quantidade abaixo do limite mínimo definido. | RF04, RF06 |

**Toda história tem requisito.** HU01 virou o RF01, HU02 o RF02, HU03 o RF03, HU04 o RF04/RF06 e HU05 o RF05.

**Todo requisito tem origem.** Todos os requisitos vieram de falas diretas do Gabriel Schactae, das histórias de usuário ou das características descritas na seção 4.1.

**O que a conferência mudou.** A lista cobriu 100% dos itens do escopo sem deixar pendências funcionais.
