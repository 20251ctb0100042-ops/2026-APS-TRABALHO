# 4.2.3 Modelagem de Classes

## Dos substantivos às classes

As classes saem dos substantivos. A fonte principal é o fluxo do caso de uso *Cadastrar Ingredientes e Fichas Técnicas*, especificado na 4.2.2. Cada elemento que o ator informa ou que o sistema valida e confirma é algo que o sistema precisa guardar. A segunda fonte é a lista de requisitos da 4.2.1. O que aparece em ambas vira classe com elevado nível de confiança.

Nem todo substantivo vira classe. Aplicam-se três filtros: o que é detalhe de outra coisa vira atributo (a quantidade necessária de um ingrediente é detalhe da receita). O que é interface não entra (ecrã de cadastro, botão guardar, alerta de stock baixo). O que está fora do sistema também não (a prateleira da despensa, a balança física da cozinha).

| Substantivo | De onde veio | Vira | Por quê |
|---|---|---|---|
| utilizador / funcionário | passo 1 do fluxo, HU01, RF01 | classe **Utilizador** | o sistema regista quem acede ao módulo e autoriza alterações de stock e receitas |
| gestor de cozinha / cozinheiro | ator da 4.2.2, passo 1, RNF02 | classe **GestorCozinha** | herda de Utilizador, possuindo permissões para aprovar fichas técnicas e ajustes |
| ingrediente | passo 3, RF02, RF03 | classe **Ingrediente** | a definição da matéria-prima no catálogo (ex.: Farinha de Trigo, Açúcar, Ovos) |
| lote | passo 4 ("lote dentro da validade"), exceção E2, e a 4.1 | classe **LoteIngrediente** | a cozinha possui várias remessas do mesmo ingrediente com validades distintas. O consumo é feito por lote |
| receita / ficha técnica | passo 5, RF08, RF09 | classe **Receita** | define como um prato/produto é preparado e quais ingredientes consome em que quantidades |
| item da receita | passo 5, RF08 | classe **ItemReceita** | classe associativa que define a quantidade e unidade específica de um ingrediente numa receita |
| fornecedor | passo 3, RF04 | classe **Fornecedor** | a empresa ou distribuidor que fornece os ingredientes para a cozinha do Gabriel |
| movimento de stock | passo 7, RF05, RF06 | classe **MovimentoStock** | o registo de entrada, baixa por receita ou perda de um lote (quem, quanto, qual lote e motivo) |
| data de validade | passo 5, RF07 | atributo de **LoteIngrediente** | detalhe de um lote físico específico, não existe isoladamente |
| prateleira, balança | falas da 4.2.1 | nada | estão fora do sistema de software. A balança é o instrumento físico utilizado na preparação |

## Classes

As classes que formam a estrutura do módulo do Gabriel possuem três faixas: nome no singular com inicial maiúscula, atributos no formato `nome: tipo` e operações com parênteses. Cada atributo e operação possui a sua origem mapeada.

A classe `Ingrediente` representa o catálogo e liga-se a `Receita` através da classe `ItemReceita`, permitindo calcular a baixa automática do stock quando um prato é confecionado. O stock físico é controlado em `LoteIngrediente` para garantir a rotatividade adequada (FIFO/PEPS).

| Classe | Atributos | Operações | Veio de |
|---|---|---|---|
| **Utilizador** | - nome: String, - matricula: String, - perfil: String | + autenticar(): boolean | passo 1 (identificação), RNF02 (acesso restrito) |
| **GestorCozinha** | _herda de Utilizador_ | + aprovarReceita(): void, + aprovarAjuste(): void | RNF02: aprovação de fichas técnicas e perdas no stock |
| **Ingrediente** | - nome: String, - unidadeMedida: String, - stockMinimo: double | + verificarStockBaixo(): boolean, + getStockTotal(): double | RF01 (cadastro do item), RF03 e passo 4 (alerta de reposição) |
| **LoteIngrediente** | - codigoLote: String, - dataValidade: Data, - quantidadeAtual: double | + darBaixa(qtd: double): void, + estaVencido(): boolean | passo 7 ("atualiza quantidade do lote"), RF04, exceção E2 |
| **Receita** | - nomePrato: String, - rendimentoPorcoes: int, - custoEstimado: double | + calcularCustoTotal(): double, + darBaixaEmStock(porcoes: int): void | RF08 (fichas técnicas) e RF09 (baixa por produção) |
| **ItemReceita** | - quantidadeNecessaria: double, - unidade: String | + calcularCustoItem(): double | RF08 (composição da receita e dosagem de ingredientes) |
| **Fornecedor** | - razaoSocial: String, - cnpj: String, - telefone: String | + listarIngredientesFornecidos(): List | RF04 (vínculo com o fornecimento das matérias-primas) |
| **MovimentoStock** | - dataHora: DataHora, - quantidade: double, - tipoMovimento: TipoMovimento | + registrarMovimento(): void | passo 5 e RF07 (registo da ação), RF06 (histórico de consumo) |

A Figura 2 apresenta a estrutura completa das classes e os seus relacionamentos:

- **Associações:** 
  - Um `Utilizador` realiza zero ou vários `MovimentoStock` (`1` para `0..*`).
  - Um `LoteIngrediente` sofre zero ou vários `MovimentoStock` (`1` para `0..*`).
  - Um `Fornecedor` fornece um ou vários `Ingrediente` (`1` para `1..*`).
  - Um `ItemReceita` utiliza exatamente um `Ingrediente` (`1..*` para `1`).
- **Herança:** O triângulo vazado aponta de `GestorCozinha` para `Utilizador`. `GestorCozinha` é uma especialização de utilizador com privilégios de aprovação de fichas técnicas e ajustes manuais de inventário.
- **Composição (Parte e Todo):** O losango cheio encontra-se no lado do todo:
  1. No lado de `Ingrediente` com `LoteIngrediente` (`1` para `1..*`): o lote é parte da existência física do ingrediente no catálogo. Se o ingrediente for removido do sistema, os seus lotes associados deixam de existir.
  2. No lado de `Receita` com `ItemReceita` (`1` para `1..*`): o item da receita é parte integrante da ficha técnica. Eliminando a receita, eliminam-se as suas composições de ingredientes.

## Teste de objetos

Para validar o diagrama e as suas multiplicidades, simula-se um cenário real da cozinha: o gestor Gabriel prepara 5 porções da receita "Bolo de Chocolate", que consome 1 kg de Farinha de Trigo do lote `LOT-2026-02` (fornecido pela "Moinho Central"), estando o lote `LOT-2026-01` esgotado.

**Figura 3 – Diagrama de objetos: preparação de receita e baixa automática de ingrediente**

![Diagrama de objetos](../diagramas/objetos.png)

Fonte: Autoria própria (2026).

| Objeto | Classe | Valores |
|---|---|---|
| `gabriel` | GestorCozinha | nome = "Gabriel", matricula = "COZ-01", perfil = "GestorCozinha" |
| `moinhoCentral` | Fornecedor | razaoSocial = "Moinho Central Ltda", cnpj = "12.345.678/0001-90", telefone = "(42) 3220-0000" |
| `farinhaTrigo` | Ingrediente | nome = "Farinha de Trigo Especial", unidadeMedida = "KG", stockMinimo = 15.0 |
| `lote01` | LoteIngrediente | codigoLote = "LOT-2026-01", dataValidade = "10/05/2026", quantidadeAtual = 0.0 |
| `lote02` | LoteIngrediente | codigoLote = "LOT-2026-02", dataValidade = "25/08/2026", quantidadeAtual = 24.0 |
| `boloChoc` | Receita | nomePrato = "Bolo de Chocolate", rendimentoPorcoes = 10, custoEstimado = 35.00 |
| `itemFarinha` | ItemReceita | quantidadeNecessaria = 1.0, unidade = "KG" |
| `movBaixaReceita` | MovimentoStock | dataHora = "08/11/2026 14:00", quantidade = 1.0, tipoMovimento = SAIDA_PRODUCAO |

**Ligações:** `moinhoCentral` e `farinhaTrigo`, `farinhaTrigo` e `lote01`, `farinhaTrigo` e `lote02`, `boloChoc` e `itemFarinha`, `itemFarinha` e `farinhaTrigo`, `gabriel` e `movBaixaReceita`, `lote02` e `movBaixaReceita`.

**O que o teste confirma**

- **A receita conecta ingredientes sem duplicar o stock.** O objeto `boloChoc` liga-se a `itemFarinha`, que aponta para o catálogo `farinhaTrigo`. A baixa real de 1 kg ocorre de forma precisa sobre `lote02`.
- **Um ingrediente possui múltiplos lotes e fornecedor definido.** O objeto `farinhaTrigo` liga-se ao fornecedor `moinhoCentral` e aos lotes (`lote01` e `lote02`).
- **Auditabilidade do processo.** O objeto `movBaixaReceita` regista a data, hora, quantidade e o gestor responsável (`gabriel`), garantindo a rastreabilidade integral da produção.
