# 4.2.2 Modelagem de Casos de Uso

## Atores

Dois papéis usam o sistema de estoque da forneria de cookies. O ator é o papel, não a pessoa. Nas histórias da 4.2.1, o Gabriel fala como proprietário. No diagrama, os atores são divididos conforme o perfil definido nas seções 4.1 e 4.2.1: **Operador** (que abrange o proprietário e a equipe da cozinha) e **Atendente / Auxiliar**.

| Ator | Quem é | O que faz no sistema |
|---|---|---|
| **Operador** | Proprietário (Gabriel Schactae) e equipe da cozinha | Cadastra ingredientes, cadastra embalagens, altera saldos e consulta alertas de estoque. |
| **Atendente / Auxiliar** | Equipe de atendimento e balcão | Consulta a disponibilidade de embalagens e ingredientes no inventário. |

---

## Casos de uso

Cada caso de uso é um objetivo que um ator alcança no sistema. O nome é o mesmo do requisito que ele atende, letra por letra.

Nem todo requisito vira elipse. O RF06 (Filtrar inventário por categoria) é um recurso visual de consulta que ocorre no meio do acompanhamento do estoque. Ele aparece como passo do fluxo alternativo da especificação.

| Caso de uso | Ator | Atende |
|---|---|---|
| **Cadastrar ingrediente** | Operador | RF01 |
| **Cadastrar embalagem** | Operador | RF02 |
| **Atualizar saldo de estoque** | Operador | RF03 |
| **Consultar alerta de estoque** | Operador, Atendente / Auxiliar | RF04 e RF06 (o filtro do inventário é o fluxo alternativo A1) |
| **Autenticar operador** | nenhum: é incluído por Cadastrar ingrediente, Cadastrar embalagem e Atualizar saldo de estoque | RF05 |

## Especificação do caso de uso principal

Atualizar saldo de estoque é o caso de uso que o sistema existe para fazer: é ele que mantém o inventário real de ingredientes e embalagens. Por isso é o especificado.

| Campo |  |
|---|---|
| Caso de uso | Atualizar saldo de estoque |
| Ator | Operador |
| Pré-condição | O operador está autenticado no sistema (RF05) e o item (ingrediente ou embalagem) está cadastrado (RF01 ou RF02). |
| Pós-condição | O saldo do item está atualizado no inventário com o novo valor (RF03). |

**Fluxo principal**

1. O operador solicita a visualização do item no inventário.
2. O sistema exige a identificação do operador («include» Autenticar operador).
3. O sistema apresenta o saldo atual do item selecionado.
4. O operador informa a movimentação (entrada ou saída) e a quantidade.
5. O sistema registra a alteração do saldo de estoque.

**Fluxo alternativo**

- **A1, no passo 1: o operador aplica um filtro por categoria.** O operador filtra a exibição entre ingredientes ou embalagens (RF06) e o fluxo retorna ao passo 3.

**Fluxos de exceção**

- **E1, no passo 2: a autenticação falha.** O sistema avisa que as credenciais são inválidas e finaliza o caso de uso sem a pós-condição.
- **E2, no passo 5: a saída informada é maior que o saldo existente.** O sistema exibe mensagem de saldo insuficiente e cancela a operação. O caso de uso termina sem a pós-condição.  A confirmar com o cliente: o sistema deve permitir saldo negativo para emergências de produção?

## Rastreabilidade com a 4.2.1

| Requisito | Caso de uso | Onde aparece |
|---|---|---|
| RF01 Cadastrar ingrediente | Cadastrar ingrediente | elipse |
| RF02 Cadastrar embalagem | Cadastrar embalagem | elipse |
| RF03 Atualizar saldo de estoque | Atualizar saldo de estoque | elipse e especificação |
| RF04 Consultar alerta de estoque | Consultar alerta de estoque | elipse |
| RF05 Autenticar operador | Autenticar operador | elipse e passo 2 do fluxo principal |
| RF06 Filtrar inventário por categoria | nenhuma elipse | fluxo alternativo A1 de Consultar alerta de estoque |

**Todo requisito tem lugar.** Cinco viraram elipse com o mesmo nome. O RF06 não virou elipse, e a tabela diz onde ele mora.

**Toda elipse tem requisito.** Nenhum caso de uso apareceu sem um requisito por trás.

**O que a especificação mudou.** Escrever a exceção E2 mostrou a dúvida sobre como tratar saldos negativos na rotina rápida da cozinha. Ela ficou anotada com ❓ para a próxima conversa com o Gabriel.
